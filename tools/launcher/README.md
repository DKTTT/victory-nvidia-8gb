## 快速开始

1. 解压本包到任意目录（路径不要有空格/中文问题不大，但建议英文路径）
2. 双击 `GTA6-Launcher.bat`
3. 检查「① 设备与配置」页的自动检测结果
4. 到「② 构建与下载」页选择构建（首次会自动扫描本地构建；没有就下载/编译）
5. 到「③ 预热与启动」页：先点「全部预热」，完成后再点「启动游戏」

## 自动检测与推荐规则

| 检测项 | 方式 | 影响 |
|---|---|---|
| 显卡厂商 | N 卡：nvidia-smi / WMI；A 卡：WMI + 注册表 | **N 卡（NVIDIA）→ vf-nvidia 分支；A 卡（AMD/Radeon）→ 上游主线 vf-main/upstream/7900** |
| 双显卡（核显 + 独显） | 自动跳过 Intel 核显，**优先 A/N 独显**，再按显存大小挑 | 不会被核显顶掉（以前会误判成 "Intel 不支持"） |
| 显存 | N 卡用 nvidia-smi；A 卡 WMI 会截断到 4GB，改读注册表 `qwMemorySize` | 决定渲染分辨率：<7GB→480p；7~9GB→540p；10~12GB→720p；≥12GB→1080p；≥20GB→1440p |
| 主机模式 | A 卡 → Series X；N 卡 → Series S | 渲染缩放按对应基准换算 |
| CPU / 内存 / 系统 | WMI | 显示信息（内存 <16GB 建议关后台程序） |

推荐结果会显示在「推荐配置」框里，可以用页面下方的「主机模式 / 渲染分辨率」手动覆盖。

> **A 卡和 N 卡都支持**：两边的区别只在「用哪个构建」——N 卡用 NVIDIA 分支（wave32 兼容最好），A 卡用上游主线（原生 wave64，不需要模拟）。预热、启动、排行榜推荐的流程完全一致。

## 目录设置

| 目录 | 用途 |
|---|---|
| 游戏目录 | 含 `game_scarlett_master.exe` 和 `shaders.rpf` 的目录 |
| 构建根目录 | 存放各个 victory 工程（含 `target/diag/victory.exe` 或 `target/release/victory.exe`）的根目录，启动器会递归扫描 |
| 缓存根目录 | 着色器/管线缓存；已知构建自动映射：vf-nvidia→cache-nvidia、vf-main→cache-upstream、cool_fox→cache-coolfox |
| 存档根目录 | 游戏存档与配置；vf-nvidia→perf-data、vf-main→perf-data-up |

所有路径会保存到 `launcher-config.json`，下次打开自动恢复。

## 从 GitHub 下载构建

「② 构建与下载」页：

- **仓库**：`用户名/仓库名`（默认 `DKTTT/victory-nvidia-8gb`）
- **分支**：默认 `tools-and-patches`
- **下载源码 ZIP**：下载 `codeload.github.com/仓库/zip/refs/heads/分支` 并解压到「下载到」目录
- **下载 Release**：读取 GitHub 最新 Release，选 Windows/x64 附件下载
- **编译选中的源码构建**：调用 `cargo build --profile diag -p victory --features diagnostics`（需要已安装 Rust 工具链）

下载使用系统代理（墙内请先开代理）。下载完成后点「重新扫描本地构建」即可选用。

## 预热与启动

- **预热着色器**：`victory shaders shaders.rpf`（2~5 分钟，可中断续传）
- **预编译管线**：`victory warm --used`（3~10 分钟，可中断续传）
- **全部预热**：先着色器，完成后自动接续管线预编译（进度条 + 实时日志 + 停止按钮）
- **检查预热状态**：不用开游戏，实时读缓存目录判断「已就绪 / 还差几条 / 版本变了要重做」
- **启动游戏**：自动套用渲染缩放（按分辨率换算）、两平面合成修复白屏、纹理等待修复、光追跳过列表等参数

### 缓存状态是怎么判断的（v1.9.1 起）

以前只看「exe 修改时间 vs 上次预热时间」，重新编译一次就永远判「过期」，而且预热刚做完还可能弹「从未预热」。现在改成三件事一起看：

| 依据 | 说明 |
|---|---|
| 预热记录 | 缓存目录里的 `launcher-warm.json`：着色器/管线分别记录时间、指纹、是否跑完；**跟着缓存目录走**，换构建根目录、重新扫描都不会丢 |
| 版本指纹 | 翻译器源码指纹（同 `victory-gpu/build.rs` 的输入）+ git commit + 显卡驱动版本，只有真的变了才判过期 |
| 缓存文件 | `shaders\` 里的目录/文件数、`pipelines\warm-done.txt` 里当前指纹的行数、`early-pipelines.txt` 还差多少条 |

判定结果会写进日志（`build=… warmShaders=… pipesFingerprint=… fpLines=… missingEarly=…`），排查问题直接看日志。

## 常见问题

**Q: 启动后白屏？**
确认构建是 vf-nvidia / vf-main 且 `VICTORY_COMPOSE=1`（启动器自动设置）。

**Q: 预热很慢？**
管线预编译受显卡驱动 PSO 编译速度限制，首次 3~10 分钟属正常；中断后下次继续。

**Q: 预热完启动还是提示「没预热」？**
v1.9.1 已修：启动前会**实时重算**缓存状态（旧版用的是选构建时的旧结果）。若仍提示，点「检查预热状态」把日志里的 `build/warmShaders/pipesFingerprint` 一起发出来。

**Q: 点「更新并编译」界面卡住？**
v1.9.1 起 `git fetch / git pull` 全部在后台跑，日志实时输出、界面不卡；编译本来就是后台的，编译结束后的重新扫描也改成后台。只有真在编译时 CPU 会满。

**Q: 提示找不到 victory.exe？**
构建根目录要指向含 `目标工程/target/diag/victory.exe` 的目录；用「重新扫描本地构建」确认。

**Q: 想用自己编译的版本？**
把工程放在构建根目录下，编译出 `target/diag/victory.exe` 或 `target/release/victory.exe` 后重新扫描即可。

## 已知限制

- Intel 核显/其他显卡不在支持范围（会提示）
- 自动检测显存对非 NVIDIA 卡可能不准（WMI 4GB 上限问题），可手动改分辨率
- 从 GitHub 下载源码后需要自备 Rust 工具链才能编译
## 上游更新管理（新增）

启动器能管理构建的上游更新，避免「更新后白屏/变慢」的坑：

| 功能 | 说明 |
|---|---|
| 版本显示 | 选中构建后显示 `分支@commit`、翻译器指纹、缓存状态 |
| 缓存状态 | 按「预热记录 + 版本指纹 + 缓存文件」三者判断（见上一节）；没有版本记录的老缓存按文件时间兜底 |
| 检查上游更新 | 对 git 工程在**后台**执行 `git fetch`（走代理），实时显示进度，完成后报落后多少个提交 |
| 更新并编译 | 自动备份当前 exe → **后台** `git pull --ff-only` → 自动接续**后台**编译；全程不卡界面 |
| 回滚上一版本 | 从 `victory.exe.bak-*` 恢复上一个可用的 exe |
| 启动前提醒 | 只有「从没预热过 / 版本对不上」才弹窗；部分预热只写日志，不拦启动 |

**建议流程**：检查更新 → 更新并编译 → 全部预热 → 启动。更新前启动器会自动留备份，不满意可回滚。

> 已知问题：上游 2026-11-26 的 93 提交版本在 8GB NVIDIA 上实测白屏/崩溃，暂不建议更新。

## 排行榜与自动推荐（新增）

启动器每次打开都会从 **GTA VI PC Race**（`vuyp.github.io/gta6-pc-race`）拉取最新排名：

- 数据源：`https://vuyp.github.io/gta6-pc-race/src/data.json`（每 15 分钟更新一次，48 个项目）
- 显示：前 25 名的 排名 / 阶段 / 画面分 / 速度分 / 稳定分 / 仓库
- **本机推荐**：按显卡厂商、显存、速度、稳定性、排名综合打分，列出前 3 个最适合你的项目
- **本地构建在榜情况**：每个本地构建对应榜上哪个项目、第几名（含已知问题标注）
- **★ 本地最适合你的构建**：从你已有的构建里挑出最匹配的（自动排除已知白屏的构建）
- 网络失败时自动使用上次缓存（`race-cache.json`）

> 排行榜数据是各项目自报 + 第三方核实，仅供参考；启动器推荐的是"最适合本机硬件"的项目，不代表一定能玩。

## 键盘映射（新增，⑤ 标签页）

自己绑键：每行一条 `源键 = 目标键`，`#` 开头是注释。

```
CapsLock = Escape
F1 = Tab
W = Up
```

- 可用键名：`A-Z 0-9 F1-F12 Space Enter Esc Tab Shift Ctrl Alt CapsLock Backspace Up Down Left Right Home End PgUp PgDn Insert Delete Num0-Num9`，也可以直接写 `0x41` 这样的 VK 值
- **只在游戏窗口聚焦时生效**（不影响打字/浏览器）
- `Ctrl+Alt+M` 随时开/关映射
- 勾选「启动游戏时自动开启映射」→ 启动游戏自动启用；关闭启动器自动卸载
- 实现：系统级低级键盘钩子（`keymap.cs`）；若被杀毒软件拦截会提示安装失败

> 注意：部分游戏用 DirectInput 原始输入时，键盘钩子可能收不到；本游戏（GameInput）实测可用。

## v1.8.0：推荐算法 v2（修正偏差 + 速度 21s → 5s）

旧算法的问题（用户日志证实）：
1. **只在另一家显卡上测试的项目也会得到 0.3 分**（AMD-only 项目对 NVIDIA 用户不够低）
2. **显存信息解析过宽**：可能把内存 GB 当成显存，导致 24GB 卡项目不降权
3. **速度取"最高帧"**：轻场景 30fps 会被当成 6/6，实际重场景可能 5fps
4. **没测稳定性的项目被当 0 分**（不公平地惩罚在研项目）
5. **每个项目都跑一次 git 查本地构建** → 推荐耗时 **21 秒**

v2 规则：
| 因素 | 权重 | 说明 |
|---|---|---|
| 厂商匹配 | 4.0 | 只认 `tested.gpu` 里真实出现的厂商；只在另一家测试 = **0 分** |
| 显存接近 | 2.0 | 从 "with N GB / N GB card" 严格解析；4~32GB 范围；未知=中性 0.5 |
| 速度 | 1.5 | 用**最低 fps**（最差场景）分档；未知=中性 |
| 稳定性 | 1.0 | 未测=中性 0.5（不再惩罚） |
| 画面 | 1.0 | |
| 8GB 实测证据 | +0.3 | 8GB 用户专属：项目文字提到 8GB 卡实测 |
| 本地已有构建 | +0.4 | 你本地有对应构建 → 优先推荐可直接用的 |
| 排名加成 | ≤0.2 | 弱化社区排名噪声 |

速度修复：把"本地仓库→构建名"映射改为**循环前预计算一次**，打分时查表；推荐耗时从 **21 秒降到约 5 秒**。

实测对比（NVIDIA 8GB）：
- v1.7.3：VI-BR-PORT 7.88 > AnyXboxX 7.85 > ztrx 7.37（#23 与 #2 几乎同分）

## v1.8.1：编译不再卡死 GUI + 编译进度可见

## v1.9.0：修复 legacy 包「有声音没画面」+ 按构建能力补 env

**根因**（用户日志与包对照确认）：
- legacy 包 `start-8gb.bat` 把 `set VICTORY_RESOLUTION=1920x1080` / `VICTORY_CARD_BUFFERS_MB` 写在 `victory.exe run` **之后**（且在 pause 后）→ 永远不生效
- 标题按 3840×2160 出画，窗口 fit 到约 1848×1040 几乎盖满屏幕 → flip chain/DWM 合成失败 → **黑屏/白屏，但音频正常**

**修复**：
- 启动器 Build-Env 现在按构建能力自动选画面方案：
  - 新构建（exe 含 `VICTORY_RENDER_SCALE`）→ `RENDER_SCALE` + `OWN_UPSCALER` + `COMPOSE`
  - legacy 构建（不含）→ `VICTORY_RESOLUTION=<宽>x<高>` + `CARD_BUFFERS_MB=1024`，不再设无效的 RENDER_SCALE
- 所有构建统一 `VICTORY_WINDOW_PERCENT=88`（避免窗口盖满屏幕触发 flip chain 黑屏）
- 日志会打印「构建类型: 新构建/legacy」和实际 env，便于排查
- 已修复 legacy 包 bat 顺序并重打包：`legacy-GTA6-VIctory-8GB-20261125.zip`、`legacy-GTA6-VIctory-12GBplus-20261125.zip`（原文件已留 .bak）
- 新出 `20261126b` 分发包：`GTA6-VIctoryPerf-8GB-20261126b.zip`、`GTA6-VIctoryPerf-12GBplus-20261126b.zip`

## v1.9.1：修「预热完还说没预热」+ 更新不再卡界面

用户反馈两件事：预热一小时、启动还是弹「从未预热」；点「更新并编译」界面卡死。

**一、预热状态（重写判定）**

| 旧问题 | 根因 | v1.9.1 |
|---|---|---|
| 预热完启动仍弹「没预热」 | 启动前的弹窗用的是**选构建时**算出来的旧结果，预热完成后没更新 | 启动前实时重算 |
| 记录读不到 | 记录按**工程路径**当 key，重扫/换路径就对不上 | 记录写进**缓存目录**（`launcher-warm.json`），并兼容旧 `builds-meta.json`（路径/exe/缓存目录三种查找） |
| 编译后永远「过期」 | 用 exe 修改时间比较，重新编译必然更新 | 改比**版本指纹**：翻译器源码指纹 + commit（短/全长 sha 兼容）+ 驱动版本 |
| 预热被停止/关窗口 = 白做 | 只有完整跑完才写时间戳 | 每个阶段（着色器 / 管线）跑完或中断都记录，下次续传；完成度单列 |
| 判定靠日志关键字 | 引擎改一行输出就失效 | 看缓存文件本身：`shaders` 文件数、`warm-done.txt` 当前指纹行数、`early-pipelines.txt` 差集 |

**二、界面卡顿**

- `git fetch`（检查更新）、`git pull`（更新并编译）改成**后台进程 + 实时日志**，界面全程可操作
- 编译结束后的**重新扫描构建**（原来同步扫 30 秒以上）改成后台作业，回来只填列表
- `检查上游更新` 的非 git 分支（GitHub API）放进后台作业
- **顺手修了 `停止` 按钮不生效**：PS 5.1 的 `Process.Kill($true)` 不存在，原来的停止/关窗口根本没杀掉进程树，会残留 7~8 个 `victory warm --these` 子进程占满 CPU、锁住缓存（启动时报 0x80070005 的元凶之一）。现在按父子关系整棵树结束；启动时只清理「孤儿」残留（父进程还在的不动，开新预热时会提示而不是硬抢）。

**三、说明**

- 老的 `builds-meta.json` 仍然兼容：新版优先读缓存目录里的记录，读不到再按工程路径/exe 路径/缓存目录去旧文件里找
- 预编译包（无源码）的指纹只看 exe 内容：重新解压同一份 exe 不会被判成「构建变了」
- 只有「从没预热」或「版本对不上」才弹窗；中断/部分预热只写日志，不拦启动

## v1.9.5：目录自动扫描 + 管线预热不再“看着像没跑”

**目录**：默认值里不再有任何写死的路径。启动时自己找——`game_scarlett_master.exe` 所在目录当游戏目录，含 `*/target/diag|release/victory.exe` 的目录当构建根目录；缓存/存档就近放在启动器旁边的 `gta6\`、`gta6\work\`（写不进去就用 `%LOCALAPPDATA%\GTA6Launcher`）。找到的结果会写进日志，① 页随时可改。

**管线预热**：引擎的 `warm` 遇到一批“编不出来”的管线会静默收尾（不打印汇总），所以以前常常只编几十条就停住。现在：

| 行为 | 说明 |
|---|---|
| 自动续传 | 一轮结束若剩余条数在减少，就自动再跑一轮（最多 8 轮） |
| 并发按显存 | `warm --used --jobs N`：≤8GB→4、≤12GB→6、更大→8（可用 `GTA6_LAUNCHER_WARM_JOBS` 覆盖） |
| 编不出来的单列 | 最后一轮无进展 → 判定“驱动/引擎拒绝编译”，状态写「缓存就绪（…另有 N 条被拒绝编译）」，不再一直显示未完成 |

本机实测：以前停在第 137 条；现在跑完 3100/3143，剩下 48 条明确标成“编不出来”。

**状态判定**：「跑完过 + 后来游戏又用到新管线」= 缓存就绪（只提示），只有「记录里没跑完」才报未完成。

## v1.9.4：diag / release 两份 exe 时选较新的

同一个工程既有 `[diag]` 又有 `[release]` 时，默认选**较新**的那份（以前按扫描顺序先命中 diag，刚编出来的 release 反而不被采用）。日志会写：`默认构建: vf-nvidia [release]（11-26 23:53）`。

## v1.9.3：不支持预热的构建，选中就告诉你

| 旧行为 | 现在 |
|---|---|
| 点「预编译管线」跑一趟，只得到「预热没有产出」 | 选中构建时跑一次 `victory.exe --help`（约 140ms，按 exe 缓存），直接判定这个 exe 支持哪些预热步骤 |
| 不知道是没跑成、还是根本做不了 | 构建列表标 `[不支持预热]`；状态栏/检查按钮显示「**该构建不支持预热**（victory.exe 没有 shaders / warm 子命令，旧版构建）」 |
| 「全部预热」对着不支持的构建白跑 | 只有 warm 就只做管线、只有 shaders 就只做着色器；两个都没有就直接提示、不启动进程 |
| 旧构建启动前被弹「没预热」 | 「不支持预热」只提示、不拦启动（游戏会边跑边编译） |

**遇到这个提示怎么办**：换 `20261126a/b` 分发包，或在「② 构建与下载」用「更新并编译」把该构建升到含 `warm` 的版本（本机实测新版 `victory --help` 里 `warm` / `shaders` 都在）。

**顺带修的**：配置里写着 `E:\gta6` 但机器上只有 `D:` 时，以前会在控制台刷 `Join-Path : 找不到驱动器`，现在路径拼接不再碰文件系统，盘不存在就自动回退到启动器目录下的 `gta6\` 并在日志提示一次；下载时的蓝色进度窗口也关掉了。
