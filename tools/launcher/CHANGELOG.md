## 最近更新摘要（v1.9.1 → v1.9.9）

从旧版本升上来的话看这一段就够了；每个版本的细节在下面各自的段落里。

**预热（最影响体验）**
- 跑完一次完整预热就显示「缓存就绪」，不再永远「没跑完」；之后游戏又用到新管线只作提示
- 管线预热遇到引擎提前收尾会自动续传（最多 8 轮），并按显存配并发：本机实测从停在 137 条 → 跑完 3146 条
- 剩下确实编不出来的单独列出「另有 N 条被驱动/引擎拒绝编译」，不影响已完成的缓存
- 旧版 `victory.exe` 没有 `warm` / `shaders` 子命令时，选中构建就提示「该构建不支持预热」，不再白跑一趟
- 空缓存点「预编译管线」不再被误判成「已全部编完」

**启动与路径**
- 所有目录自动扫描（游戏目录、构建根目录），缓存/存档就近生成；配置里不再内置作者的路径
- 路径和盘符失效会自动回退并提示，不再抛 `Join-Path : 找不到驱动器`
- 路径带空格也能用（以前 `GTA6 Xbox …` 被拆成多个参数，预热/启动一闪就退）

**显卡**
- A 卡 / N 卡都认：核显 + 独显的机器取独显；A 卡显存改读注册表（WMI 对 >4GB 会读错）
- A 卡推荐上游主线 + Series X + 按显存给档位（≥20GB → 1440p）
- 新增「关闭光追」开关（按 shader 哈希跳过 RT 绘制，A/N 卡通用；引擎侧只在 diag 构建生效）
- 分辨率单选会说明这个构建认哪条路（`VICTORY_RENDER_SCALE` / `VICTORY_RESOLUTION` / 都不认）

**界面**
- 排行榜页「本地构建在榜」那行改成可横向滚动，不再被窗口边缘截断
- 同一工程有 diag / release 两份 exe 时，默认选较新的那份
- 下载构建时不再弹蓝色「正在写入 Web 请求」进度窗

## [v1.10.1] - 2026-11-27

### 新增：游戏退出/崩溃后自动“翻译”日志

以前崩了只有一句「已记录崩溃 #N」，原因得自己翻几 MB 的日志。现在退出时会读 `game-*.log` 与 `.err`，命中已知问题就写成中文建议（同时附在 `crash-*.log` 末尾）：

| 日志特征 | 启动器给出的结论 |
|---|---|
| `the library did not load it … 0x80070057` | 有 N 条管线没从 PSO 库里读到（库里没有这条）→ 运行时会现场重编；再点「预编译管线」补齐 |
| `FFX FSR4 … FAILED hr=0x80004001` | 标题在走 FSR4 管线库反序列化，HLE 未实现，共 N 次回退重编 → 试 `VICTORY_OWN_UPSCALER=0` |
| `device removed` / `0x887A0007` | 显卡设备被驱动移除（TDR）→ 降一档分辨率 / 关光追 / 更新驱动 / 别再开别的 3D 程序 |
| `0x887A0004` | 设备接口或功能级别不受支持 → 驱动太老或系统不支持该 D3D12 特性 |
| `build unknown (b99f876b…)` | 只是名字表没有这条；hash 前缀 `b99f876b` 就是 1.0.2.1，分辨率补丁照样生效 |

## [v1.9.9] - 2026-11-27

### 澄清 + 修复：①页的「渲染分辨率 / 主机模式」到底改了什么

实测三个真实 exe（在二进制里找环境变量字符串）：

| exe | `VICTORY_RENDER_SCALE` | `VICTORY_RESOLUTION` | `VICTORY_WINDOW_PERCENT` |
|---|---|---|---|
| vf-nvidia 系列 | ✅ | — | — |
| 20261126a / b 分发包 | ✅ | ✅ | ✅ |
| legacy 20261125 包 | — | ✅ | — |

**结论：有用，但分两条路 —— 以前启动器不告诉你走的是哪条。**

| 构建 | 单选的作用 |
|---|---|
| 有 `VICTORY_RENDER_SCALE` | 设 `scale = 目标高度 ÷ 基准高度`，引擎（loader）直接改标题的渲染目标与 FSR 常量；范围 0.2–1.0，且只对 1.0.2.1 主程序打补丁 |
| 只有 `VICTORY_RESOLUTION`（legacy） | 设 `VICTORY_RESOLUTION=宽x高`（例如 960x540） |
| 两个都没有 | 单选对它**完全无效** |

- 主机模式（Series S / Series X）只是换算基准：Series S=1080、Series X=2160。同一个 540p 在 Series S 上是 scale 0.5、Series X 上是 0.25，像素数一样，差别在 upscaler 的基准
- **选中构建时现在会检测并写日志**：`分辨率: 支持 VICTORY_RENDER_SCALE：分辨率单选有效` / `只支持 VICTORY_RESOLUTION（老构建）` / `⚠ 这个构建不认任何分辨率变量：①页的分辨率/主机模式对它无效`
- `VICTORY_WINDOW_PERCENT=88` 只有 20261126b 认，其它构建不再设置（以前是给不认的构建也塞了一个无效变量）

## [v1.9.8] - 2026-11-27

### 新增：关闭光追开关（A 卡 / N 卡通用）

「③ 预热与启动」新增勾选框 **关闭光追（跳过 RT 绘制，A/N 卡通用）**，默认勾选。

| 项 | 说明 |
|---|---|
| 原理 | 通过 `VICTORY_SKIP_PIPELINES` 传一组 shader 哈希，引擎在绘制前把命中这些哈希的 RT 绘制整条跳过。**按哈希匹配，跟 NVIDIA / AMD 无关**，所以 A 卡、N 卡都能用 |
| 清单 | 优先用构建自带的 `<构建>\scripts\rt_off_hashes.txt`；没有就找启动器目录下的 `rt_off_hashes.txt`；都没有会明确写日志「本次不跳过任何绘制」 |
| 日志 | 启动时打印：`关闭光追：跳过 N 条 RT 管线（清单 rt_off_hashes.txt，A/N 卡通用）` / 取消勾选时打印「正常渲染光追」 |
| 引擎限制 | 引擎里这段代码是 `#[cfg(feature = "diagnostics")]`——**只有 diag（诊断）构建生效**，`release` 构建会直接忽略。勾了但用 release 构建时，日志会提醒这一点 |

> 想要 release 构建也生效，需要改引擎那一行 `cfg` 后重新编译；默认的 diag 构建（`cargo build --profile diag --features diagnostics`）本来就带。

## [v1.9.7] - 2026-11-27

### 修复（路径带空格 → 预热/启动“闪一下就完成”）

用户游戏在 `S:\GAME\GTA6 Xbox v1 0 2 1 CYBERLEEK`，日志里是：

```
error: unexpected argument 'Xbox' found
Usage: victory.exe run [OPTIONS] <EXE> [-- <TITLE_ARGS>...]
```

| 旧行为 | 原因 | 现在 |
|---|---|---|
| 预热/启动一闪就结束 | `Start-Process -ArgumentList` **不会**替带空格的路径加引号，`GTA6 Xbox …` 被拆成 3 个参数，clap 直接报错退出 | 新增 `Quote-Arg`：带空格的路径自动加引号（`shaders`、`run`、`git -C` 全部走它），路径里有空格也能正常预热/启动 |
| 显示“预热完成”但其实什么都没做 | 判定层把三种“没干活”当成了完成 | 见下 |

### 修复（“闪一下完成”的判定漏洞）

| 旧行为 | 原因 | 现在 |
|---|---|---|
| 空缓存点「预编译管线」→ 秒完成 | 引擎在没有任何管线记录时也会打印 `0 to make`，老逻辑 = “全部编完” | `0 to make` 且缓存里 0 条管线 → 判定为「缓存里还没有任何管线记录：先启动一次游戏玩几分钟，再点「预编译管线」才有意义」，不再报完成 |
| 预热记录里写着“完成”，缓存却是空的 | 只看记录不看文件 | 记录说完成但缓存里没有对应文件 → 视为未完成 |
| 状态栏把“预热完成”跟“从未预热过”拼在一起 | `Save-WarmRecord` 无条件加前缀 | 只有缓存真就绪（`ok`）才说「预热完成」，否则写「预热结束：…」；构建不支持预热的记录不再打这个前缀 |
| 引擎报参数错误时只看到“没有产出” | 没解析 stderr | 会从 stderr 提炼：`引擎拒绝了这次调用… 它把 'Xbox' 当成了多余参数：说明某个带空格的路径被拆开了` |

## [v1.9.5] - 2026-11-27

### 目录全部自己扫描（不再内置任何“作者机器”的路径）

| 以前 | 现在 |
|---|---|
| 默认值写死 `E:\GTA6.Xbox…`、`E:\gta6\work`、`E:\gta6` | 默认全空，启动时自己找 |
| 换台机器一开就报 `Join-Path : 找不到驱动器 E` | 拼接不再碰文件系统（`[System.IO.Path]::Combine`），盘不存在自动换路 |
| 缓存/存档要手动填 | 自动放在启动器旁边的 `gta6\`、`gta6\work\`（写不进去就用 `%LOCALAPPDATA%\GTA6Launcher`） |

自动检测规则：**游戏目录** = 含 `game_scarlett_master.exe` 的那层（逐盘、名字像游戏的目录优先，最多两层）；**构建根目录** = 含 `*/target/diag|release/victory.exe` 的目录（只在候选目录里找，不整盘递归）；找到什么都会写进日志（`路径: 自动找到…`），随时可在 ① 页改。

### 管线预热：不再“看着像没跑”

引擎的 `warm --used` 遇到一批编不出来的管线会**静默收尾**（`warm.rs` 里 `_ => break`，连汇总行都不打印），所以以前经常出现“点了没反应 / 一直说没产出”。

| 现在 | 说明 |
|---|---|
| 自动续传 | 一轮结束若“还差的条数”变少就自动再来一轮（最多 8 轮），每轮都有日志 |
| 并发按显存给 | `warm --used --jobs N`：≤8GB→4、≤12GB→6、更大→8（每个子进程一个 D3D12 设备，开太多容易互相挤掉）；可用 `GTA6_LAUNCHER_WARM_JOBS` 覆盖 |
| 编不出来的单列 | 最后一轮没有新进展 → 判定为“驱动/引擎拒绝编译”，记为 `PipesRefused`，状态写「缓存就绪（…另有 N 条被拒绝编译）」，**不再永远显示未完成** |

实战数据（本机 8GB / 驱动 621.24）：以前停在第 137 条再也不动；加上续传后跑完 **3146/3146**（0 to make），只有 2 条被驱动拒绝，状态显示「缓存就绪」。

> 兼容性：老构建的 `warm` 可能不认 `--jobs` 参数（会 `unexpected argument` 然后 0 产出）。启动器发现“第一轮毫无进展”时会自动去掉该参数重试一次，不会把这种情况误报成“预热没有产出”。

### 状态判定修正

- 「跑完过 + 之后游戏又用到新管线」= **缓存就绪**（只附一句提示）。以前无条件按差集报“未完成”，这也是“预热完还说没预热”的来源之一。
- 「记录里没跑完 + 还差 N 条」才报「管线预热未完成：还差 N 条（可续传）」。

## [v1.9.1] - 2026-11-26

### 修复（预热完仍提示「没预热」）

用户实测：预热很久，启动还是弹「从未预热」；重新编译一次又永远判「缓存过期」。

| 旧行为 | 根因 | v1.9.1 |
|---|---|---|
| 启动前弹「没预热」 | 弹窗用 `$script:cacheState`（**选构建时**算的旧结果），预热完成后从未更新 | 启动前 `Test-LaunchCacheGate` **实时重算** |
| 记录读不到 | `builds-meta.json` 用**工程路径字符串**当 key，重扫/移动/大小写不一致就查不到 | 记录写进缓存目录 `launcher-warm.json`；旧 meta 仍兼容（工程路径 → exe 路径 → 缓存目录三级查找，key 规范化） |
| 编译后永远过期 | 用 exe 修改时间和预热时间比较，重新编译必然「更新」 | 改比**版本指纹**：翻译器源码指纹（仿 `victory-gpu/build.rs` 的输入）+ commit（短 sha / 全长 sha 前缀兼容）+ 显卡驱动版本 |
| 停止/关窗口 = 白做 | 只有完整跑完才写时间戳；`all` 链式预热时着色器阶段不落盘 | 每个阶段完成或中断都记录（`shadersDone/shadersComplete/pipesDone/pipesComplete`），可续传 |
| 判定依赖日志关键字 | 引擎输出一改就失效 | 以**缓存文件**为准：`shaders` 文件数、`warm-done.txt` 当前指纹行数、`early-pipelines.txt` 差集；日志关键字只作补充 |
| 弹窗时机不对 | 部分预热/只有着色器也拦 | 只有 `never`/`stale` 弹窗，`partial` 只写日志 |

新增「检查预热状态」按钮：不开游戏即可看到 缓存就绪 / 还差 N 条管线 / 版本变了要重做，日志里带 `build / warmShaders / warmPipes / translator / commit / driver / pipesFingerprint / fpLines / missingEarly` 全量诊断。

### 修复（`停止` 按钮无效 + 残留进程）

- **根因**：`Process.Kill($true)` 是 .NET Core 3.0+ 的重载，PowerShell 5.1（.NET Framework）上直接抛异常被 `catch{}` 吞掉 → 停止按钮和关窗口**从未真正杀掉**预热进程。
- 实测残留：1 个 `victory warm --used` + 6 个 `victory warm --these` 子进程继续占 CPU、锁缓存文件（启动报 `0x80070005` 的元凶之一）。
- 修复：`Stop-ProcTree` 按 `Win32_Process` 父子关系结束整棵树（预热 / 编译 cargo+rustc / 游戏通用）；`Clear-StaleWarmProcs` 在启动器启动和开始预热前清理上次残留。

### 新增/修改（更新不再卡界面）

| 操作 | 旧 | v1.9.1 |
|---|---|---|
| 检查上游更新（`git fetch`）| 同步阻塞，代理慢时界面假死 | 后台进程 + 实时日志 + 耗时显示 |
| 更新并编译（`git pull`）| 同步阻塞，之后才启动（本来异步的）编译 | 备份 exe → **后台** pull → 自动接续后台编译；成功/已是最新/失败按 HEAD 变化与输出判断 |
| 检查上游更新（非 git 构建，GitHub API）| `Invoke-RestMethod` 同步，最长 20s 假死 | 后台作业 |
| 编译结束 / 下载完成 / 回滚后重新扫描构建 | 同步递归扫描 10~35s（编译完那一刻卡死）| 后台作业扫描，回来只填列表 |
| 「重新扫描本地构建」按钮 | 同步 | 后台 |
| 启动时扫描 | 仍同步（窗口刚出现，等 10s）| 不变 |

> 说明：PS 5.1 里带 `-RedirectStandard*` 的 `Start-Process` 拿不到 `ExitCode`（实测恒为空），所以后台进程的成败改为看**输出文本 + 命令自身的副作用**（如 pull 后 HEAD 是否变化、fetch 后能否 `rev-list`）。

### 其它

- 预编译包（没有源码的构建）的版本指纹只看 exe 内容，重新解压/复制同一个 exe 不再被判成「构建变了」。
- 启动时清理残留 warm 进程只清「孤儿」（父进程已不在的）；父进程还活着的视为别人正在跑的预热、不动它，开新预热时会提示而不是硬抢。
- `launcher-config.json` 不再把键位页的示例注释当成用户配置写入。
- 版本号：脚本头部与启动日志 → v1.9.1。
