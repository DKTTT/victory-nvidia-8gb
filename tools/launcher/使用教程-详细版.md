## 1. 这是什么

这是一个用于启动 **GTA VI 的 Xbox 版（Series X|S 包）PC 移植项目 VIctory** 的图形启动器。它把"运行游戏"需要的所有手工步骤自动化了：

- **自动检测硬件**（显卡厂商/显存/CPU/内存）→ 推荐合适的构建和画质
- **管理构建**：扫描本地编译好的 victory.exe、从 GitHub 下载/编译新构建
- **预热**：启动前把着色器翻译和管线编译做完，避免游戏里现场编译造成卡死
- **上游更新管理**：检查上游更新、更新并编译、出问题一键回滚
- **排行榜**：自动拉取 GTA VI PC Race 社区排名，按你的硬件推荐项目，并可一键拉取构建
- **键盘映射**：自定义按键（例如把 CapsLock 映射成 Escape）

> 注意：游戏本体、Xbox 包、以及这些第三方移植项目都不是本启动器提供的。
> 启动器只负责"用合适的参数去跑它们"。

## 2. 运行环境与准备

### 必需的

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 64 位 |
| 显卡 | NVIDIA（RTX 系列，8GB 显存以上最佳）或 AMD RDNA2 及以上 |
| 内存 | 建议 16GB 以上（8GB 显存 + 32GB 内存最佳实践） |
| 游戏本体 | 含 `game_scarlett_master.exe` 和 `shaders.rpf` 的目录 |
| 构建程序 | 本地已编译好的 `victory.exe`（或从 GitHub 下载） |

### 可选的

| 项目 | 用途 |
|---|---|
| Rust 工具链（rustup + cargo） | 从源码编译构建 |
| Visual Studio Build Tools | 编译 Rust 项目时需要 |
| 代理（默认 127.0.0.1:7890） | 访问 GitHub 下载/检查更新 |
| 游戏手柄（Xbox 手柄最佳） | 部分构建用键盘操作有难度 |

### 第一次运行前要确认

1. 游戏目录里确实有 `game_scarlett_master.exe` 和 `shaders.rpf`
2. 显卡驱动是最新的（NVIDIA 建议 Game Ready 驱动）
3. 如果要从 GitHub 下载：能访问 github.com（国内需要代理）

## 3. 安装与首次启动

### 安装

1. 下载 `GTA6-Launcher-v1.4.zip`
2. 解压到任意目录（建议 **英文路径**，例如 `D:\Tools\GTA6Launcher`）
3. 双击 `GTA6-Launcher.bat`

> 不要直接在 zip 里运行；必须解压。
> 目录里需要保留 `keymap.cs`（键盘映射功能用）。

### 首次启动会发生什么

1. 窗口打开，自动检测硬件（1~2 秒）
2. 自动扫描构建根目录下的 victory.exe
3. 1.5 秒后自动拉取排行榜
4. 日志框显示：

```
GTA VI 自动启动器 v1.4 by DKTTT
检测硬件…
硬件: NVIDIA / NVIDIA GeForce RTX 3070 Ti Laptop GPU / 显存 8 GB
扫描到 15 个本地构建
选中构建: vf-nvidia [diag] -> ...
默认构建: vf-nvidia
排行榜已更新
```

### 提示杀毒软件

如果杀毒软件报毒：
- 启动器是 PowerShell 脚本 + C# 键盘钩子，容易被误报
- 添加信任/白名单即可
- 键盘映射（keymap.cs）需要安装系统级键盘钩子，这是正常行为

## 5. ① 设备与配置

### 硬件检测

打开后自动显示：

```
显卡: NVIDIA GeForce RTX 3070 Ti Laptop GPU
厂商: NVIDIA    显存: 8 GB
CPU : 12th Gen Intel(R) Core(TM) i9-12900H (14 核 / 20 线程)
内存: 31.7 GB
系统: Microsoft Windows 11 专业版
```

- NVIDIA 显卡用 `nvidia-smi` 读真实显存
- 其它卡用 WMI 读取（可能不准，可手动改分辨率）

### 推荐配置

启动器会根据硬件给出建议：

| 检测结果 | 推荐 |
|---|---|
| NVIDIA | 构建 vf-nvidia（wave32 兼容最好） |
| AMD | 构建 vf-main/上游主线（原生 wave64） |
| 显存 <7GB | 480p |
| 显存 7~9GB | 540p |
| 显存 10~12GB | 720p |
| 显存 ≥12GB | 1080p |
| 主机模式 | NVIDIA→Series S；AMD→Series X |

可以手动覆盖：页面下方「主机模式」「渲染分辨率」单选框。

### 目录设置

| 目录 | 填什么 | 示例 |
|---|---|---|
| **游戏目录** | 含 game_scarlett_master.exe 和 shaders.rpf | `E:\GTA6.Xbox.v1.0.2.1` |
| **构建根目录** | 存放 victory 工程的根目录 | `E:\gta6\work` |
| **缓存根目录** | 着色器/管线缓存 | `E:\gta6` |
| **存档根目录** | 游戏存档/配置 | `E:\gta6\work` |

点「浏览…」选择。设置会保存到 `launcher-config.json`，下次不用重填。

**已知构建的缓存/存档自动映射**：

| 构建名 | 缓存目录 | 存档目录 |
|---|---|---|
| vf-nvidia | cache-nvidia | perf-data |
| vf-main | cache-upstream | perf-data-up |
| cool_fox | cache-coolfox | perf-data-cool |

这样可以直接复用之前预热好的缓存，不需要重新预热。

## 6. ② 构建与下载

### 本地构建列表

点「重新扫描本地构建」，会递归扫描构建根目录下所有：

```
<工程>/target/diag/victory.exe
<工程>/target/release/victory.exe
```

显示格式：`名称 [diag/release] 大小 MB 时间`

- 启动器会按硬件**智能选择**默认构建（NVIDIA → vf-nvidia）
- 选中后会显示：分支@commit、翻译器指纹、缓存状态
- 缓存状态（v1.9.1 起按「记录 + 版本指纹 + 缓存文件」判断）会提示：
  - `缓存就绪（着色器 N 个 · 管线 M 条 · 预热 时间）` —— 可用
  - `管线预热未完成：还差 N 条` —— 点「预编译管线」续传
  - `缓存可用，但着色器/管线 上次没跑完` —— 中断过，继续即可
  - `⚠ 构建已更新 / 翻译器或构建已变化 / 显卡驱动已更新` —— 需要重新「全部预热」
  - `从未预热过` —— 先「全部预热」
- 详细判定过程（`build / warmShaders / translator / commit / driver / fpLines / missingEarly`）都打在日志框里

### 从 GitHub 下载构建

| 控件 | 说明 |
|---|---|
| 仓库 | `用户名/仓库名`，默认 `DKTTT/victory-nvidia-8gb` |
| 分支 | 默认 `tools-and-patches`，会自动检测默认分支 |
| 下载到 | 下载和编译的工作目录 |

三个按钮：

1. **下载源码 ZIP**：从 `codeload.github.com/仓库/zip/refs/heads/分支` 下载并解压（需要自己编译）
2. **下载 Release**：读取 GitHub 最新 Release 的 Windows/x64 附件直接下载（如果有）
3. **编译选中的源码构建**：对选中的工程执行
   `cargo build --profile diag -p victory --features diagnostics`

> 下载走系统代理；编译需要 Rust 工具链。

### 上游更新与回滚

| 按钮 | 作用 |
|---|---|
| **检查上游更新** | 对 git 工程执行 `git fetch`（走代理），**后台执行**，显示落后几个提交、上游最新提交 |
| **更新并编译** | 自动备份当前 exe → **后台** `git pull --ff-only` → 自动接后台编译 → 标记缓存过期 |
| **回滚上一版本** | 从 `victory.exe.bak-时间戳` 恢复上一个可用 exe |

> v1.9.1：`git fetch / git pull` 都在后台进程里跑，进度实时打进日志框，界面全程可点；编译结束后的重新扫描也改成后台作业（以前编译完那一刻会卡 10~35 秒）。

**推荐流程**：

```
检查上游更新 → 更新并编译 → 全部预热 → 启动游戏
出问题 → 回滚上一版本
```

**代理**：默认 `http://127.0.0.1:7890`，你的代理端口不同就改这里。

**已知问题**：上游 2026-11-26 的 93 提交版本在 8GB NVIDIA 上实测白屏/崩溃，不建议更新。

## 7. ③ 预热与启动

### 为什么必须预热

游戏第一次用到某个着色器/管线时，驱动要现场编译（每个可能 100ms~2s），会造成：
- 进入新场景卡死几秒
- 树木/平视/新区域疯狂卡顿
- 严重的 stutter

**预热 = 提前把这些都编译好**，之后游戏里直接命中缓存。

### 三个预热按钮 + 检查预热状态

| 按钮 | 执行内容 | 耗时 |
|---|---|---|
| 预热着色器 | `victory shaders <游戏目录>\shaders.rpf` 翻译全部 25,694 个着色器 | 2~5 分钟（有缓存几秒） |
| 预编译管线 | `victory warm --used` 编译游戏实际用到的管线 | 3~10 分钟 |
| **全部预热** | 先着色器，完成自动接续管线 | 10~15 分钟 |
| 检查预热状态 | 不开游戏，直接读缓存目录判断（v1.9.1）| 秒级 |

- 有进度条和百分比
- 「停止」可随时中断，下次继续（断点续传）；停止会**连同子进程一起结束**（旧版没杀干净会残留 7~8 个 `victory warm` 占 CPU）
- 每完成一个阶段就写记录：`<缓存目录>\launcher-warm.json`（着色器/管线各记时间、指纹、是否跑完）
- 缓存是否可用按「记录 + 版本指纹（翻译器源码 / commit / 驱动）+ 缓存文件」判断，**重新编译不再误判过期**；只有真的换了版本才要求重新预热
- 老版本留下的缓存（没有记录文件）也能识别：按 `shaders` 文件数 + `warm-done.txt` 行数认，不会误报「从没预热」

### 启动游戏

点「启动游戏」后会：

1. 检查是否已有 victory 进程（有则拒绝并提示 PID；上次预热残留的进程会在启动器启动时自动清理）
2. **实时**重算缓存状态：只有「从没预热」/「版本对不上」才弹窗确认；部分预热只写日志不拦
3. 设置环境变量：
   - `VICTORY_GAME_DIR` / `CACHE_DIR` / `DATA_DIR`
   - `VICTORY_RENDER_SCALE`（按分辨率换算，540p/1080p=0.5）
   - `VICTORY_OWN_UPSCALER=1`（标题自身上采样）
   - `VICTORY_COMPOSE=1`（两平面合成，修白屏）
   - `VICTORY_TEXTURE_NO_WAIT=0` / `STAGE_MS=500`（修皮肤黑块）
   - 光追跳过列表 `VICTORY_SKIP_PIPELINES`
4. 启动 `victory.exe run game_scarlett_master.exe --execute --console series-s`

启动后启动器保持响应；勾选「关闭启动器时一并结束游戏」可以一键收拾。

## 8. ④ 排行榜与推荐

### 数据来源

- `https://vuyp.github.io/gta6-pc-race/src/data.json`
- 社区项目 **GTA VI PC Race** 每 15 分钟更新
- 启动器**每次打开自动拉取**，离线时用本地缓存

### 列表内容

前 25 名项目，每行显示：

```
排名. 项目名      阶段  画面x/5 速度x/6 稳定x/4   仓库
 1. victory-fork    st6  画面2/5 速度4/6 稳定3/4   fxceless/victory-fork
```

阶段说明：7=可玩，6=进入游戏，5=可辨认画面，4=第一帧，3=图形设备…

### 拉取构建（新功能）

1. **点选**列表中的项目（或**双击**）
2. 点「拉取选中项目构建」
3. 启动器会检查**硬件适配**：

```
选中项目：VIctory-Belobug-AMD（榜上第 4 名）
测试硬件：AMD
可能的适配问题：
  - 该项目只在 AMD 显卡上测试
你的配置：NVIDIA / 8 GB 显存 / 31.7 GB 内存

仍然继续拉取并构建吗？
  是 = 继续
  否 = 取消
```

4. 选「是」后选择拉取方式：

```
  是 = 下载源码并编译
  否 = 只下载源码 ZIP
  取消 = 不拉取
```

5. 自动检测默认分支 → 下载 → 解压 →（选编译时）cargo 编译 → 自动刷新构建列表
6. 回到「②构建」选择新构建，再去「③」预热

> 没有公开仓库的项目（CGBJ、ztrx 等已删库）会提示无法拉取。

### 本机推荐

按以下规则打分：

| 因素 | 权重 |
|---|---|
| 显卡厂商匹配 | 3.0 |
| 显存接近程度 | 2.0 |
| 速度分（fps） | 1.5 |
| 稳定性分（时长） | 1.0 |
| 画面分 | 1.0 |
| 排名加成 | 0.5 |

显示前 3 名 + 每个项目的测试硬件和仓库。

### 本地构建在榜情况

启动器会读取每个本地构建的 git 远端，匹配排行榜项目：

```
vf-nvidia  → 榜上 VIctory-NVIDIA（第 29 名, 速度 6/6）
vf-main    → 榜上 VIctory-NVIDIA（第 29 名）
vf-latest  → 榜上 victory-fork（第 1 名）
cool_fox   → 榜上 CGBJ（第 11 名）⚠ 白屏（已知问题）
★ 本地最适合你的构建: vf-latest（对应 victory-fork 第 1 名）
```

## 9. ⑤ 键盘映射

### 为什么需要

- 游戏某些操作键位别扭
- 手柄不在身边时用键盘玩
- 把 CapsLock 之类没用的键映射成有用键

### 写法

每行一条 `源键 = 目标键`，`#` 开头是注释：

```
# 我的映射
CapsLock = Escape
F1 = Tab
W = Up
```

### 可用键名

```
A-Z 0-9
F1-F12
Space Enter Esc Tab
Shift Ctrl Alt CapsLock Backspace
Up Down Left Right Home End PgUp PgDn Insert Delete
Num0-Num9
```

也支持直接写 VK 值：`0x41 = 0x1B`

### 使用步骤

1. 「⑤ 键盘映射」页输入映射
2. 点「保存映射」写入配置
3. 点「启动映射」立即生效
4. 或勾选「启动游戏时自动开启映射」
5. 游戏里按 `Ctrl+Alt+M` 随时开关
6. 「测试按键」+ 底部状态栏可看最后捕获的键（验证钩子是否工作）
7. 关闭启动器自动卸载

### 重要说明

- **只在游戏窗口聚焦时生效**，不影响浏览器/聊天软件
- 某些游戏用 DirectInput 原始输入时可能收不到键盘钩子
- 杀毒软件可能拦截键盘钩子（会提示安装失败）

## 12. 疑难排查

### 启动报 `0x80070005`（拒绝访问）

**原因**：已有 victory 进程/预热进程占着缓存或存档文件。

**处理**：

```cmd
taskkill /F /IM victory.exe /T
taskkill /F /IM game_scarlett_master.exe /T
```

等 3 秒再启动。v1.4 会先检测并提示 PID，不会静默失败。

### 白屏

- 确认选的是 vf-nvidia / vf-main 构建
- 启动器已自动设置 `VICTORY_COMPOSE=1`（两平面合成，修 Series S 白屏）
- 如果仍白屏：② 回滚上一个可用构建

### 启动闪退

1. 看日志框最后几行
2. 确认游戏目录正确（能找到 game_scarlett_master.exe）
3. 确认缓存目录可写
4. 尝试 ② 换一个构建

### 预热中断/很慢

- 直接重新点「全部预热」，会断点续传
- 管线预编译受驱动 PSO 编译速度限制，首次 3~10 分钟正常

### 提示缓存过期

- 点「全部预热」重新走一遍
- 如果构建是刚更新/编译的，缓存必然过期，这是正常提醒

### 找不到构建

- 构建根目录要包含 `*/target/diag/victory.exe` 或 `*/target/release/victory.exe`
- 用「重新扫描本地构建」
- 新下载的源码需要先编译

### GitHub 下载失败

- 检查代理（默认 `http://127.0.0.1:7890`）
- 启动器的下载使用系统代理，请确认系统代理开着
- 也可以手动下载 zip 解压到构建根目录再扫描

### 键盘映射没反应

- 确认映射已启动（状态栏"启用中"）
- 确认游戏窗口在前台（只在聚焦时生效）
- 按 `Ctrl+Alt+M` 切换开关试试
- 杀毒软件可能拦截钩子，加白名单
- 某些游戏原始输入模式收不到钩子

### 排行榜拉取不到

- 需要能访问 `vuyp.github.io`
- 离线时使用上次缓存（`race-cache.json`）
- 点「立即刷新排名」重试

## 13. 性能建议

针对 **8GB 显存 NVIDIA**（如 RTX 3070 Ti Laptop）：

| 设置 | 建议 |
|---|---|
| 主机模式 | Series S（更快） |
| 渲染分辨率 | **540p**（均衡）；卡就降到 480p；720p 以上会明显变慢 |
| 画质 | 游戏内手动调低阴影/植被/绘制距离 |
| 后台程序 | 关掉浏览器/录屏，省内存和 GPU |
| 驱动 | 保持最新 |

**实测数据**（RTX 3070 Ti Laptop 8GB，540p）：

- 静止：约 150 ms/帧（6~7 fps）
- 转视角/树木：约 168 ms/帧（GPU 100% 满载）

> 看树木/远景卡是 GPU 满载导致的，降分辨率是最有效的办法。

## 14. FAQ

**Q: 启动器会不会修改游戏文件？**
A: 不会。游戏本体不动，只读取；缓存/存档写在你设置的目录。

**Q: 可以同时开两个游戏吗？**
A: 不行。缓存/存档文件会冲突（0x80070005），启动器已做多开检测。

**Q: 换机器要重新预热吗？**
A: 需要。缓存按显卡驱动/构建版本区分，建议重新「全部预热」。

**Q: 更新启动器会丢配置吗？**
A: 不会。`launcher-config.json` 在启动器目录，覆盖升级时保留。

**Q: 排行榜数据可信吗？**
A: 各项目自报 + 第三方核实，仅供参考；推荐只代表硬件匹配度。

**Q: 这个启动器能玩其他游戏吗？**
A: 不能。只针对 GTA VI Xbox 包 + VIctory 移植项目。

## 附：v1.6 崩溃记录与自动清理

启动器在「③ 预热与启动」页显示：`崩溃记录：N 次 / 10（满 10 次自动清理日志）`。

每次点「启动游戏」：

1. 游戏输出自动重定向到 `logs\game-时间.log` 和 `logs\game-时间.log.err`
2. 游戏退出时自动判断是否崩溃：
   - 日志出现 `upload_file_minidump` / `BacktraceBreakpad` / `panic` / `device removed` / `0x887A0006` / `DXGI_ERROR_DEVICE`
   - 进程退出码非 0
   - 启动后 10 秒内退出
3. 崩溃时写入 `logs\crashes.jsonl`（时间/原因/构建/主机模式/分辨率/缓存目录/运行秒数/最后 30 行日志），同时另存 `logs\crash-时间.log`
4. 累计到 **10 次**自动清理：
   - `crashes.jsonl` 归档为 `crashes-archive-时间.jsonl`
   - 游戏日志只保留最近 2 个，其余删除
   - 日志框提示"崩溃记录已达 10 次：旧日志已归档…"
5. 「打开日志目录」按钮可直接打开 `logs` 文件夹

排查建议：把 `logs\crash-*.log` 和 `crashes.jsonl` 最后一条发给开发者即可定位。
