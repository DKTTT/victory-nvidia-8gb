# 使用教程（图文步骤）

作者：DKTTT · 2026-11-26

---

## 第 0 步：准备

1. 解压 `GTA6-Launcher-v1.0.zip` 到任意目录
2. 确认已安装：
   - Windows 10/11 64 位
   - 显卡驱动（NVIDIA 建议最新 Game Ready）
   - 游戏本体目录（含 `game_scarlett_master.exe` 和 `shaders.rpf`）
3. 如果从 GitHub 下载构建，需要能访问 GitHub（墙内请开代理）

## 第 1 步：打开启动器

双击 `GTA6-Launcher.bat`。

窗口分三个标签页：

| 标签 | 用途 |
|---|---|
| ① 设备与配置 | 看硬件检测结果、改目录、覆盖推荐配置 |
| ② 构建与下载 | 选本地构建，或从 GitHub 下载/编译 |
| ③ 预热与启动 | 预热缓存、启动游戏 |

## 第 2 步：确认硬件与推荐（① 页）

打开后会自动检测，显示类似：

```
使用显卡: NVIDIA GeForce RTX 3070 Ti Laptop GPU
厂商: NVIDIA（A 卡=AMD/Radeon，N 卡=NVIDIA）    显存: 8 GB    驱动: 621.24
CPU : 12th Gen Intel(R) Core(TM) i9-12900H (14 核 / 20 线程)
内存: 31.7 GB
系统: Microsoft Windows 11 ...

推荐构建: NVIDIA 分支（vf-nvidia / vf-nv8gb）
推荐理由: N 卡（NVIDIA）：用 NVIDIA 分支（wave32 兼容最好）
主机模式: series-s    渲染分辨率: 540p（渲染缩放 0.5）
画质预设: balanced
```

- **N 卡（NVIDIA）** → 用 NVIDIA 分支；**A 卡（AMD/Radeon）** → 用上游主线（vf-main/upstream/7900），主机模式 Series X
- **双显卡机器**（Intel 核显 + 独显）：自动跳过核显、用独显；页面会列出没被使用的适配器
- 8GB 显存推荐 **540p / Series S**；12GB 以上 720p/1080p；≥20GB（如 7900 XTX 24GB）1440p
- A 卡显存从注册表读（WMI 对大于 4GB 的卡会读错）
- 不满意可以用下面的「主机模式 / 渲染分辨率」手动改

### 目录设置

| 目录 | 填什么 |
|---|---|
| 游戏目录 | 游戏本体（含 `game_scarlett_master.exe`、`shaders.rpf`）|
| 构建根目录 | 放 victory 工程的根目录（启动器会递归找 `target/diag/victory.exe`）|
| 缓存根目录 | 着色器/管线缓存目录（已知构建自动映射：`cache-nvidia`、`cache-upstream` 等）|
| 存档根目录 | 游戏存档（`perf-data`、`perf-data-up` 等）|

点「浏览…」选目录，设置自动保存，下次打开不用重填。

## 第 3 步：选择构建（② 页）

点「重新扫描本地构建」，列表会显示：

```
vf-nvidia  [diag]  13.6 MB  11-26 15:23
vf-main    [diag]  13.8 MB  11-26 18:37
...
```

- 启动器会**按硬件自动推荐**（NVIDIA → `vf-nvidia`）
- 选中一行后，下方会显示该构建的缓存/存档路径
- 没有构建？用下面的「从 GitHub 下载」：

| 按钮 | 作用 |
|---|---|
| 下载源码 ZIP | 从仓库分支下载源码并解压（需要自己编译）|
| 下载 Release | 下载 GitHub 最新 Release 的 Windows 附件（如果有）|
| 编译选中的源码构建 | 调 `cargo build --profile diag`（需要 Rust 工具链）|

## 第 4 步：预热（③ 页）

首次使用或更新构建后，**必须预热一次**：

1. 点「全部预热」
2. 先翻译着色器（2~5 分钟，命中缓存只要几秒）
3. 自动接着预编译管线（3~10 分钟，受驱动 PSO 编译速度限制）
4. 进度条 + 日志实时显示，可随时「停止」，下次继续

> 预热完成后启动游戏不会再现场编译管线，卡顿明显减少。

**怎么知道缓存到底行不行？** 点「检查预热状态」（v1.9.1 新增）：

| 显示 | 含义 |
|---|---|
| 缓存就绪（着色器 N 个 · 管线 M 条 · 预热 时间）| 可以启动（如果后面又玩出新管线，会附一句「之后游戏又用到 N 条新管线」，不影响启动）|
| 管线预热未完成：还差 N 条 | 再点「预编译管线」续传即可 |
| 缓存可用，但着色器/管线 上次没跑完 | 中断过，再点「全部预热」接着做 |
| 这个构建不支持预热（旧版 exe）| 这个 `victory.exe` 太旧、没有 `warm`/`shaders` 命令：换 20261126a/b 包，或在「② 构建与下载」点「更新并编译」升级它；加多少遍都编不出来 |

### 「预编译管线」常见情况

| 日志/状态 | 意思 | 怎么办 |
|---|---|---|
| `管线预热没跑完（还差 N 条），引擎提前收尾 → 自动继续第 X 轮` | 引擎的 `warm` 碰到编不出来的批次会静默收尾，启动器在自动续传 | 不用管，让它跑完 |
| `缓存就绪（…另有 N 条被驱动/引擎拒绝编译）` | 这 N 条这张卡/这个驱动编不出来，其余都好了 | 不用管，不影响已完成的缓存 |
| 一直停在同一个数字、日志里有 `没有新进展` | 这批管线确实编不出来 | 换驱动或换构建再试 |
| 预热期间帧数骤降 / 预热变慢 | 游戏和预热在抢同一张显卡 | 先关游戏再预热 |
| `这个构建的 warm 可能不认识 --jobs 参数` | 老构建没有并发参数，启动器已自动去掉再试 | 不用管 |
| ⚠ 构建已更新 / 翻译器或构建已变化 / 显卡驱动已更新 | 缓存失效，重新「全部预热」 |
| 从未预热过 | 先「全部预热」 |

> v1.9.1 起，预热记录写在**缓存目录**里（`launcher-warm.json`），重新扫描构建、换构建根目录都不会丢；只有翻译器源码 / commit / 驱动真的变了才判过期，重新编译一次不会再误报「过期」。

## 第 5 步：启动游戏

点「启动游戏」：
- 启动前会**实时**再查一遍缓存状态；只有「从没预热」或「版本对不上」才弹窗确认
- 自动设置渲染缩放、两平面合成（修白屏）、纹理等待、光追跳过列表
- 游戏窗口关闭后启动器恢复可点
- 勾选「关闭启动器时一并结束游戏」可以一键收拾

## 常见问题

**Q: 白屏？**
确认选的是 vf-nvidia 或 vf-main 构建；启动器已自动设置 `VICTORY_COMPOSE=1`。

**Q: 游戏闪退？**
看日志框最后几行；常见原因是构建 exe 路径不对、游戏目录不对、或缓存目录没权限。

**Q: 帧率低/看树卡？**
8GB 显存建议 540p 或 480p；看树木/远景卡是 GPU 满载导致的，降分辨率是最有效的办法。

**Q: 预热报错「找不到 shaders.rpf」？**
游戏目录填错了，要选到含 `shaders.rpf` 的那层。

**Q: 提示已有游戏在运行？**
先关掉游戏窗口，启动器防多开。

## 更新启动器 / 构建

- 启动器：解压新版覆盖（配置文件 `launcher-config.json` 会保留）
- 构建：重新编译或用 GitHub 下载，然后「重新扫描本地构建」
## 第 6 步：上游更新（可选）

如果要跟进上游新功能：

1. 「② 构建与下载」页选中你的构建
2. 点「检查上游更新」（走代理，需要能访问 GitHub）——**在后台跑，界面不卡**，日志实时显示进度
3. 有更新时点「更新并编译」（自动备份旧 exe → 后台拉取 → 自动接后台编译，全程可操作界面）
4. 更新后**必须**到「③ 预热与启动」页重新点「全部预热」
5. 出问题点「回滚上一版本」恢复旧 exe

> 只有编译那几分钟 CPU 会满；拉取、扫描构建都不再冻结界面（v1.9.1）。

注意：新版本不一定更好——上游 2026-11-26 的 93 提交版本在本机（8GB NVIDIA）实测白屏/崩溃，建议先看 README 的已知问题再更新。

## 第 7 步：看排行榜、用推荐

1. 打开启动器后切到「④ 排行榜与推荐」页
2. 会自动拉取最新排名（也可点「立即刷新排名」）
3. 下方「为本机推荐」会列出最适合你硬件的 3 个项目
4. 「你的本地构建在榜情况」显示你已有的构建对应榜上第几名
5. 「★ 本地最适合你的构建」直接告诉你该选哪个构建去玩

网络不通时会用上次缓存；数据来源 https://vuyp.github.io/gta6-pc-race/

## 第 8 步：键盘映射（可选）

1. 切到「⑤ 键盘映射」页
2. 在文本框里写映射，每行一条：`源键 = 目标键`（例如 `CapsLock = Escape`）
3. 点「保存映射」保存到配置
4. 点「启动映射」立即生效；或勾选「启动游戏时自动开启映射」，启动游戏自动启用
5. 游戏里按 `Ctrl+Alt+M` 可以随时开关映射
6. 「测试按键」按钮 + 下方状态栏可以看最后捕获的键（验证钩子是否正常）

## 第 9 步：从排行榜直接拉取构建

1. 「④ 排行榜与推荐」页，点选（或双击）一个项目
2. 点「拉取选中项目构建」
3. 如果项目测试硬件与你的配置不符（例如只在 AMD/大显存卡上测过），会弹窗提示
   `配置可能不适配 …`：**是 = 继续，否 = 取消**
4. 选择拉取方式：**是 = 下载源码并编译**（自动检测默认分支、调用 cargo、编译完自动刷新构建列表）；
   **否 = 只下载源码 ZIP**；**取消 = 不拉取**
5. 下载/编译完成后回「② 构建与下载」选择新构建，再去「③」预热

### 关闭光追（A 卡 / N 卡都能用）

「③ 预热与启动」里有个勾选框 **关闭光追（跳过 RT 绘制，A/N 卡通用）**，默认开着。

- 原理：把一组 shader 哈希传给引擎（`VICTORY_SKIP_PIPELINES`），引擎在绘制前把命中这些哈希的 RT 绘制整条跳过。按哈希匹配，跟你是 N 卡还是 A 卡无关
- 清单来自构建自带的 `scripts\rt_off_hashes.txt`；构建没带的话日志会写「本次不跳过任何绘制」，把这个文件放进构建目录或启动器目录即可
- **只在 diag（诊断）构建生效**：引擎里这段代码是 `diagnostics` 特性才编进去的，`target\release` 那份会忽略。启动日志会提示
- 想恢复光追：把勾去掉，重新点「启动游戏」即可（不用重新预热）

### 渲染分辨率 / 主机模式到底改了什么

选中构建时，启动器会检测这个 exe 认哪条路（日志里会写）：

| 构建 | 用的变量 | 效果 |
|---|---|---|
| vf-nvidia 系列、20261126a/b | `VICTORY_RENDER_SCALE` | 直接改标题的渲染目标和 FSR 常量，范围 0.2–1.0，只对 1.0.2.1 主程序有效 |
| legacy 20261125 等 | `VICTORY_RESOLUTION` | 直接给 `宽x高`，例如 960x540 |
| 两个都不认 | — | 单选无效，日志会警告 |

- **主机模式只是换算基准**：Series S=1080、Series X=2160。选 540p 时，Series S → scale 0.5，Series X → scale 0.25；两者最终都是 540p 像素，差别在 upscaler 的基准
- 想确认有没有生效：看日志里 `构建类型: 新构建（支持 RENDER_SCALE）→ VICTORY_RENDER_SCALE=0.5` 或 `构建类型: legacy → VICTORY_RESOLUTION=960x540`
